# Rive Flutter Example

A demo application showcasing Rive Flutter.

## Getting Started

The `rive` package depends on `rive_native`, and the code on GitHub may reference an unpublished version of `rive_native`. We recommend using the published version from [Pub](https://pub.dev/packages/rive):

```bash
dart pub unpack rive        # Unpack the package source code and example app
cd rive/example             # Navigate to the example folder
flutter create .            # Create the platform folders
flutter pub get             # Fetch dependencies
flutter run                 # Run the example app
```

Alternatively, clone this repository (requires building native libraries locally):

```bash
git clone https://github.com/rive-app/rive-flutter
cd rive-flutter/example
flutter pub get
flutter run
```

## Renderer benchmark

The **Renderer benchmark** page (Performance/Memory testing) draws the same
content under the Rive renderer and the Flutter renderer, so the two can be
compared on a device. Pick the renderer with the switch at the bottom of the
example list, then choose a file, how many copies, whether they share one
texture through `RivePanel`, and what else animates around them. The perf
overlay (speed chip, top right) shows Rive's update rate next to Flutter's
frame rate; on Android with `Factory.rive` those are different numbers.

Scripted runs open the page from a deep link, with a query parameter per
control:

```bash
adb shell "am start -a android.intent.action.VIEW \
  -d 'riveexample://bench?asset=rewards.riv&count=4&shared=0&renderer=rive&stats=1'"
```

Keep the outer double quotes: `adb shell` runs the string through the
device's shell, where an unquoted `&` ends the command and drops every
parameter after the first.

`stats=1` logs one `[rive-bench]` line per second instead of using the
overlay, which is how to read numbers off a device farm.
`tool/browserstack_bench.py` does that on BrowserStack across a set of
devices; `packages/rive_native/ANDROID_DEVICE_TESTING.md` covers how to use it
and what earlier runs found.

## Android build

`android/` is generated by `flutter create` and tracks the Flutter version
this repo builds with: Flutter requires a minimum Gradle version, and the
Gradle wrapper in turn requires a JDK it supports. If a Gradle or JDK version
error appears after a Flutter upgrade, regenerate the folder rather than
editing the files by hand:

```bash
cd example
rm -rf android
flutter create --platforms android --org com.example --project-name rive_example .
```

Regenerating restores the files this example adds on top of the template:
the benchmark deep link (`riveexample://bench`) and
`flutter_deeplinking_enabled` in `AndroidManifest.xml`. Re-apply them from
git after regenerating.
